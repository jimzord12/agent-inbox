## Lenses

1. **Product fit and wiring.** The live worker (`agent-inbox open` / `retry`) reaches both fixes. The replay is the same `replayPending` that reconcile uses, so there is one code path for bridge evidence on disk. Decisions.md records the change.
2. **Correctness and edge cases.**
   - The rethrow is placed first in each `catch`, so `isRejected` / `herdrCode` see only `HerdrError`s.
   - The `createTab` try also holds `recordLayout`. If the second `recordLayout` fails, there is no pane id, and retry goes to `orphanTabs` (P1: uncertain, the tab is listed as a candidate, no second tab).
   - If `finishOp(create_tab, confirmed)` fails after the pane was recorded, retry continues from the pane (P2: delivered, one tab).
   - Other `catch` blocks (workspace, tabs, readAgent, focus, blocked-start focus) wrap only the Herdr call, so they need no guard.
3. **Data integrity (lead).**
   - **False delivery.** Delivery still happens only through `commitDelivery`, after a settled Herdr state, the session id and pane check, and focus. The replay can only add `receipt_candidate_json` through `captureReceipt`. That checks capability, an unrevoked blocking status, the session id equal to `session_uuid`, an accepted prompt and every receipt field, and it keeps the first candidate.
     - P5: a pending file with a wrong session id is refused and removed. The worker blocks with `RECEIPT_INVALID` and never focuses.
     - P6: a valid pending receipt while Herdr reports a replaced session blocks with `AGENT_UNAVAILABLE` and never focuses.
     - P9: a pending file older than a `bind` rejection is dropped by the existing guard.
   - **Repeated prompt.** Unaffected. A rethrown error after `agent prompt` leaves `dispatch_prompt` as `started`. Retry's `submit` does not resend it, and `awaitReceipt` confirms it by bridge acceptance (P3: one prompt, delivered).
   - **Concurrent replayers.** The worker and a CLI reconcile can read the same file. `captureReceipt` is idempotent (first candidate wins) and both remove the file with `force`. No double effect.
4. **Contracts and privacy.** No CLI JSON shape changed for M3. The retry `STATE_CONFLICT` gained `error_code` in details, which is additive. Privacy: none found.
5. **Tests and evidence.**
   - Deletion probes:
     - A, `startAgent` guard removed: the new test fails.
     - D, replay call removed: the new test fails.
     - B, `createLayout` guard removed: all 287 pass.
     - C, `submit` guard removed: all 287 pass (M2-R2-F1).
     - E, fake Herdr change reverted: only the M2 focus test fails.
   - Mocks stay at Herdr and the clock. The spies on `Attempts` model store failures, as in round 1.
6. **Failure handling (lead).**
   - **Rethrown store errors.** `crashed()` reads the row and marks it `uncertain` with "The worker stopped unexpectedly: …" (or `fail INTERNAL` when nothing external happened). When that write is also busy, the lease lapses and reconcile marks it uncertain (P4). Each op left `started` is handled by retry: `create_tab` goes to orphan discovery, `start_agent` to `observeStart`, and `dispatch_prompt` is never resent. The cost: after a crash in `createTab`, the attempt can only be abandoned, which is the same as a real crash.
   - **The replay inside the loop.** It sits inside its own catch-all `try`, so no replay error crashes the worker.
     - P7: the pending path is a folder, so it can be neither read nor removed. The worker still delivers on a live receipt.
     - P7b: the same folder with no live receipt. The worker blocks at the deadline, after 172 ms with a 150 ms test deadline, so there is no stall.
     - A busy replay costs at most one busy timeout per poll. The deadline check runs on every iteration, so it stays bounded. A busy `this.row` right after it ends the worker through `crashed()`, as before.
7. **Simplicity and ownership.** The fix reuses reconcile's replayer instead of duplicating it. Core stays the only DB writer. The worker-to-reconcile import adds no cycle. No unasked scope.
8. **Repository and docs.**
   - INB-023's notes carry the round 1 dispositions. N5 is routed to INB-014. Decisions.md has the replay entry.
   - The commit subject names two task ids (`(INB-022, INB-023)`), where the convention names one (Note N5).

## Notes

- **N1 (P2).** After a crash between `recordLayout(pane)` and `finishOp(create_tab, confirmed)`, retry succeeds from the recorded pane but leaves `create_tab` as `started` on a delivered attempt. This is diagnostic only and the same as a real crash at that point.
- **N2.** `replayPending` reads the row for its `bind`-rejection guard outside the `captureReceipt` transaction. A refused SessionStart that commits between the two lets a receipt that the session wrote before `/clear` become the candidate. This is the same narrow window reconcile already had. It cannot cause a false delivery, because the worker checks Herdr's session id before it focuses (P6).
- **N3.** On Windows, the bridge's `renameSync` onto an existing `receipt-pending.json` can fail while the worker has that file open for its once-per-poll read. This happens only on a second busy Stop before the first file was replayed. The bridge then keeps nothing, and the attempt stays recoverable by abandon. Unlikely, not observed.
- **N4.** Round 1's N3 (retry `resume` clears `last_rejection_json`) now also applies to the worker's own replay. The defence is the same: Herdr's session id check.
