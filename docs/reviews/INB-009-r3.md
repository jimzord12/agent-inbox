## Findings

### INB009-R3-F1 - Minor - A busy Stop that lands after the refused startup brings the dropped receipt back

- **Where:** `src/bridge/hooks.ts:146` (`written_at: new Date().toISOString()`, stamped at write time, after up to two busy waits); `src/worker/reconcile.ts:91-95` (the guard compares `written_at` with the bind rejection time).
- **Scenario (probe PW1):**
  1. The session acknowledges. Its Stop hook meets a busy store and enters `stopWhileBusy`, which can take several seconds.
  2. The user runs `/clear` meanwhile. The store frees long enough for the SessionStart `bind` to refuse: the candidate is dropped, the attempt is blocked, and the hook removes a file that does not exist yet.
  3. The old Stop hook's retry meets busy again and writes `receipt-pending.json`. Its `written_at` is later than the rejection.
  4. Reconcile replays the file: `receipts_replayed 1`, and `receipt_candidate` is true on the blocked attempt.
- **Expected:** a receipt the bridge dropped on purpose cannot come back (the round 1 and round 2 dispositions).
- **Actual:** it comes back when the Stop event came before the refusal but its file was written after it.
- **Impact:** low. It needs a busy store that frees and re-locks within the Stop hook's ~8 s window, plus a `/clear` inside that window. A false delivery would still need Herdr to report the original session id in the pane (`worker.ts:468`), and after `/clear` it does not.
- **Smallest fix:** stamp `written_at` when the Stop hook starts, before the first `handle` call in `safeHandle`, and pass that stamp to `stopWhileBusy`. The existing reconcile guard then discards the late file, and the INB-002 N2 case (a Stop that really happens after a refusal) still counts. A test: refused bind, then a file whose `written_at` is earlier than the rejection, written afterwards. This is already covered by the round 1 test once the stamp means the event time, so a one-line unit test of `stopWhileBusy`'s stamp is enough.

## Notes

- **N1 (Note).** A SessionStart that meets a busy store throws in `bind`, then `failClosed` passes: neither the candidate nor the file is dropped, and the attempt is not blocked. This is the pre-existing INB-005 behaviour, out of scope for this round. The worker's Herdr session check still prevents a false delivery.
- **N2 (Note).** Deletion probe M4 (the inner catch swallows STORE_BUSY) survives as an equivalent (see lens 5). No test is needed.
- **N3 (Note).** If removing the file fails in the hook (PB2), the file stays and only reconcile's rejection-time guard protects it. That is acceptable: the failure needs a non-file at the sidecar path, or a persistent lock on it.
