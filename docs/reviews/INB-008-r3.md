## Findings

### INB008-R3-F1 (Note): `fail` still overwrites a bridge verdict

- **Where:** src/core/attempts.ts:603-606. The guard is `!terminal && …`, so `fail` writes whatever the status.
- **Scenario:**
  1. `agent start` runs SessionStart, which binds the wrong profile.
  2. Herdr then answers `agent start` with a *rejected* outcome.
  3. src/worker/worker.ts:308 calls `end("fail", "AGENT_UNAVAILABLE")`, which replaces PROFILE_LAUNCH_UNSUPPORTED with failed/AGENT_UNAVAILABLE.
  - The other `fail` call sites (preflight, create_layout, `crashed`) run before any session exists, or check the status first.
- **Expected vs actual:**
  - Expected: the profile verdict survives.
  - Actual: the code changes, though `last_rejection` still holds the bind reason.
- **Impact:**
  - Nothing is delivered and no context was sent, so `failed` is honest. Only the headline cause is lost.
  - It needs a Herdr rejection after Claude actually ran its hooks, which is implausible.
- **Smallest fix:** none needed now. If wanted, let `fail` keep an existing PROFILE_LAUNCH_UNSUPPORTED code.

### INB008-R3-F2 (Note): the new `throw new Stop()` in `watchBlockedStart` is untested on its own

- **Where:** src/worker/worker.ts:338.
- **Scenario:**
  - D3 and D5, alone or together, fail no test.
  - Without them, the `resume(…, "AGENT_BLOCKED")` guard at line 355 still stops the worker, and core's in-progress guard is covered by D1.
- **Impact:** with D3 reverted, the worker would call `herdr.focus` once on a session that already has a verdict. That is harmless. The three layers are defence in depth.
- **Smallest fix:** none required. Optionally assert in the round-2 dialog test that `fake.focused` is empty.
