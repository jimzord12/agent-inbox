## Findings

### M1-R1-F1 — Material — a startup held by a dialog cannot be focused through `focus`, and the refusal names the wrong cause

- **Where:** `src/worker/focus.ts:45-48` (session check), with `src/core/attempts.ts:660-664` (`next_actions` offers `focus` whenever `pane_id` is set) and `src/worker/worker.ts:359-385` (the only focus of a dialog-held start).
- **Scenario:** an item opens in a folder Claude has not seen. Claude shows the trust dialog; `agent start` answers `agent_not_ready`; the worker blocks `AGENT_BLOCKED`, focuses the tab once, watches for 10 minutes, then leaves. The owner comes back later, sees the blocked item with `focus` in its actions, and runs `agent-inbox focus ITEM` (or the mod's Focus, which calls the same command). Herdr reports no `agent_session` yet, because Herdr learns the session from its own SessionStart hook, which runs only after the dialog is answered (preflight §7.1 rows 1 and 4; the worker's own clear-check at `worker.ts:376` relies on this).
- **Expected vs actual:** expected (spec §10.2 "A blocked startup may be focused so the user can handle its trust/login dialog"; §13 "Login/trust/permission/question dialog: mark blocked and focus the exact pane") the attempt's own pane to be focused. Actual: probe P1 returns `AGENT_UNAVAILABLE` "Herdr reports a different session under this attempt's alias; not focusing it." No other session is there; the session simply has not reported yet.
- **Impact:** the owner cannot get back to the dialog from the inbox and is told something false; the likely next move is abandon and open again, which shows the same dialog in a second tab. The trust dialog appears for every new project folder, so this is a common first-use path, and the M3 mod inherits it.
- **Smallest fix:** in `focusItem`, for a blocking attempt whose start is held (`status` blocked with `AGENT_BLOCKED`, or `agent_session` null with `agent_status` blocked / `interactive_ready` false), focus the alias when Herdr reports it in the attempt's recorded pane; keep the strict session-id check for every other case. Focus carries no context. Add a test with the fake agent's `session` set to null during the dialog, and make the fake model that by default for `agent_not_ready` starts.

### M1-R1-F2 — Minor — `retry` calls every failed attempt "abandoned"

- **Where:** `src/cli/main.ts:152-153`, with `src/core/attempts.ts:632` (a terminal `fail` also sets `revoked_at`).
- **Scenario:** an attempt fails in preflight with `CWD_UNAVAILABLE` (CLI probe). The owner runs `agent-inbox retry ATT`.
- **Expected vs actual:** expected a message saying the attempt failed (with its code) and that a new open is the next step. Actual: `STATE_CONFLICT` "The attempt is abandoned; nothing to retry." `details` carries only `status: failed`.
- **Impact:** a misleading diagnosis in the mod and the CLI; no data effect.
- **Smallest fix:** pick the word from `error_code === "ABANDONED"` instead of `revoked_at`, and add `error_code` to `details`.

### M1-R1-F3 — Minor — the receipt does not check, and no decision waives, the "statement that it is waiting"

- **Where:** `src/core/attempts.ts:711-743` (`parseReadyMarker`), spec §9.1 step 4 and §9.2 step 7.
- **Scenario:** Claude's opening reply has an orientation and a valid marker but never says it will wait.
- **Expected vs actual:** the spec lists a waiting statement as required evidence. The code accepts any non-empty orientation; `docs/decisions.md` has no entry narrowing the requirement.
- **Impact:** low; a reliable natural-language check is not practical, and the packet already instructs the wait. The gap is only undocumented.
- **Smallest fix:** append a decision that the waiting statement is requested by the packet and opening prompt but not machine-checked (the receipt proves transport and acknowledgment only, spec §9.1 last paragraph).

### M1-R1-F4 — Minor — README status is stale after M2

- **Where:** `README.md:10`.
- **Scenario:** a reader of the public repo after M2.
- **Expected vs actual:** expected the status to say opening a session works end to end on the work profile. Actual: "opening sessions, the `/inbox` mod and the producer skill are being built".
- **Impact:** low; misleads readers about what works.
- **Smallest fix:** update the status line (or leave it to INB-016 and say so on that task).
