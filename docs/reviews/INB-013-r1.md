## Findings

### F1 — Material — blocks that are not focus failures are labelled "Focus failed"

- **Where:** mod/hooks/text.ts:351, `if (a.phase === "focus" || a.evidence.receipt_candidate)`. Pinned by test/unit/mod-details.test.ts:82, "a focus failure is told by the receipt too".
- **Scenario:** the session acknowledges, then the worker blocks while still in `await_receipt`, before any focus. Four worker paths do this:
  - worker.ts:476, `AGENT_UNAVAILABLE` "Claude closed after acknowledging; the receipt is kept."
  - worker.ts:481, `AGENT_UNAVAILABLE` "Herdr no longer reports the attempt's session in its pane."
  - worker.ts:492, `RECEIPT_INVALID` "Claude has not settled after acknowledging."
  - worker.ts:492, `RECEIPT_INVALID` "…does not report its session id."
- **Likelihood:** the "not settled" case is realistic: Claude can stay busy past the receipt timeout after acknowledging a large handoff.
- **Expected:** spec §12.1 and §13 tell "receipt captured but focus failed" apart from "Claude stopped… / not settled". No focus has been tried, and for "Claude closed" a retry will block again.
- **Actual:** the pane says "Focus failed: … its tab could not be focused. Retry only focuses it again; nothing is resent." Then it adds the real message, which contradicts it, e.g. "Claude closed after acknowledging".
- **Impact:** the person is told the wrong cause and the wrong effect of Retry, on one of the five states AC2 requires to be distinguished.
- **Smallest fix:**
  - Key "Focus failed" on `phase === "focus"` alone.
  - Give blocked-in-`await_receipt` with a receipt candidate its own label, e.g. "Acknowledged, not settled", with the stored message as the hint.
  - Correct the unit test to match.

### F2 — Minor — empty last page when a handoff ends with a line break on a 40-line boundary

- **Where:** mod/hooks/text.ts:274–298.
- **Scenario:** a handoff of 40·n lines with a final line break, which most files have.
- **Expected:** n pages.
- **Actual:** n+1 pages. The last one has an empty body and reads "Page n+1 of n+1 · lines 40n–40n of 40n" (probe 2).
- **Impact:** cosmetic and confusing. No line is lost.
- **Smallest fix:** keep a final empty piece on the previous page, even when that page already holds PAGE_LINES pieces, or drop it and record the trailing break so that `unpaginate` stays exact.

### F3 — Minor — the handoff page budget ignores the rest of the details tree

- **Where:** mod/hooks/register.tsx details render and text.ts PAGE_CHARS.
- **Scenario:** an item near the producer limits: around 30 or more references with URIs near 2048 characters, plus a long instruction and summary.
- **Expected:** a whole page drawn.
- **Actual:** the engine's 100,000-character tree bound cuts the tail of the handoff Text, "… 1130 more characters, not drawn" (probe 1, at 32 refs). The person sees the page indicator, but lines are missing from that page.
- **Impact:** only at extreme, producer-reachable sizes; realistic items are far under.
- **Smallest fix:** cap each drawn reference line (truncate the URI and label for display), or size the page from what the other fields leave.

### N1 — Note — fast page presses are likely lost in the mod, not the terminal

- **Where:** register.tsx:238.
- **Cause:** `turn` closes over the page of the last draw. Two presses before a redraw both set page+1. Redraws come "at the redraw rate" (index.d.ts, `state.set`). That matches the live result: a burst of 126 presses reached page 100.
- **Impact:** never skips a page.
- **Fix if wanted:** read the page in the handler (a new dispatch reads the latest written value), or keep it in a module variable.

### N2 — Note — the "waiting for acknowledgment" hint is premature

text.ts:343: phase `submit_context` is set before the prompt is sent (worker.ts:417). The hint "The session has the handoff and is reading it" can show before dispatch.

### N3 — Note — times are shown in UTC

They are shown in UTC and labelled so. Spec §12.1 asks for the configured local time zone for snooze; the display is not mandated. Worth revisiting when snooze lands.

### N4 — Note — the safe next action is not shown

`next_actions` is fetched but not drawn. Spec §12.1 asks for "the safe next action". This presumably arrives with INB-014's buttons; the Retry wording in the hints already covers part of it.

### N5 — Note — no test for switching items during a fetch

No engine test switches items while a details fetch is in flight (e.g. with `slowMs`). The code is correct by reasoning. The `fetchDetails` catch path writes without a generation check: at worst a brief "Loading…", no wrong data shown.

### N6 — Note — scroll on page turn not checked live

A page plus header is taller than a typical docked pane, e.g. bodyRows 30 in tests. Nobody checked live whether Next resets the pane's scroll to the top of the new page. If it does not, the top lines of each page need scrolling up to be seen.
