## Findings

### INB003-R3-F1: Minor. Some listed target codes are not proof of "nothing launched" on `agent start`

- **Where:** `src/herdr/adapter.ts:89-101` (the shared set), applied to `startAgent` at `:217-223` through `:156`.
- **Why the shared set does not fit `agent start`:**
  - `agent start` resolves its target by `--pane`. Its pre-launch misses are `agent_pane_not_found` / `agent_pane_unavailable`, and `pane_not_found` in the resolver.
  - The name is new, so `agent_not_found` ("agent target … not found") has no pre-launch path on this verb.
  - Neither does `workspace_not_found` or `tab_not_found`.
  - So if any of the three ever reaches the caller from `agent start`, it would come from the CLI's post-launch wait loop: polling the new agent after its pane or tab closed, or after the agent deregistered. That is the same reasoning that excluded `agent_name_not_found` in round 2.
- **Evidence status:** the binary strings do not show the wait loop passing these codes through. The post-launch cluster uses `agent_name_not_found`, `agent_kind_mismatch`, `agent_not_ready`, and "agent process exited before becoming interactive". So this is unproven, which is why it is Minor and not Material.
- **Scenario:** the worker calls `startAgent`. Claude launches, then the owner closes the tab during startup, and the CLI's poll forwards `agent_not_found`.
- **Expected:** `unknown`, so the worker reconciles through `tab get` / `agent get`.
- **Actual:** `rejected`.
- **Impact:** low. A closed pane usually means the process is gone. But the worker could relaunch with the same `--session-id` on the belief that nothing ran.
- **Smallest fix:** make the pre-effect set per verb, or treat `agent_not_found`, `workspace_not_found` and `tab_not_found` as `unknown` when the call is `agent start`. Add one test (`agent_not_found` on `startAgent` gives unknown). Alternatively, record why not and let INB-010 inject that fault.
