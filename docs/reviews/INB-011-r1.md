## Lenses

1. **Product fit and wiring** — `agent-inbox focus` (src/cli/main.ts:172) reaches `focusItem`; `get` (main.ts:48) reaches `attemptSummaries`. AC#1 met: `agent get` precedes `agent focus` and the session UUID and pane are compared first (focus.ts:35-47; test asserts verb order). AC#2 met: a missing alias records `closed`, a different session or pane records `unknown`, and neither calls `agent focus` (tests 2 and 3 assert `fake.focused` unchanged). Spec §13 "target closes after delivery": item stays in History, receipt and session UUID kept (test 2). §4.2 step 9: focus dropped for `closed`, reference always kept.
2. **Correctness and edge cases** — Mapping is right for delivered attempts. Herdr restart that drops all names: `agent_not_found` -> `closed`, which matches §13 (a restored pane id is not proof of continuation, and a lost name means the process is gone); an unreachable or restarted server on another socket -> `unavailable`. Weak spots: the same mapping is applied to blocking attempts, where "no agent yet" is not "closed" (F3); availability writes are unconditional and can be stale (F3); the 20-row cap hides the delivered attempt in an extreme history (F2).
3. **Data integrity** — `setAvailability` touches only `availability` and `updated_at`; status, receipt, lease, fencing generation and item placement are untouched. `commitDelivery` still sets `live` atomically. No path marks anything delivered. Nothing reads `updated_at` for lease or staleness, so the extra bump is harmless.
4. **Contracts and privacy** — `AttemptSummary` selects explicit columns; no capability, challenge, packet bytes, packet path or binding (P3). `profile_id` and `session_uuid` are intended references. Focus success shape `{attempt_id, session_uuid, focused, availability}`; every focus error now carries `attempt_id` and `session_uuid`, `AGENT_UNAVAILABLE` adds `availability`, `HERDR_UNAVAILABLE` adds `herdr_code` (retryable). Loose typing and missing truncation signal noted (F2, N1). Privacy check of the diff and task notes: none found.
5. **Tests and evidence** — Deleting `seen("closed")`, `seen("unknown")`, `seen("unavailable")`, the next_actions guard or `attempts` in `get` each fails a test. Deleting `seen("live")` fails nothing (P1, F1). "Newest first" is not asserted: test 5 sorts ids and the fake clock gives ties (N2). Mocks only at Herdr.
6. **Failure handling** — Herdr failures are loud, retryable, carry the reference and keep the item where it was. A non-Herdr exception from `herdr.agent` is now reported as retryable `HERDR_UNAVAILABLE` with `herdr_code: "error"` instead of propagating (N3).
7. **Simplicity and ownership** — Availability writes go through `Attempts.setAvailability` (core); the worker module only decides the value. Summary query lives in `Inbox`. No unasked scope.
8. **Repository and docs** — Task notes describe the mapping and the "refreshed only by focus" choice accurately; commit subjects follow the convention. That choice (no Herdr call on read, mod shows stored value) is a design decision the mod (INB-013) depends on and is not in `docs/decisions.md` (N4).

## Findings

### INB011-R1-F1 — Minor — a successful focus restoring `live` is untested

- **Where:** src/worker/focus.ts:48; test/unit/worker.test.ts (INB-011 block, tests 1 and 4).
- **Scenario:** delete `seen("live");` and run `bun run test`.
- **Expected:** a test fails, since recovery from `unavailable`/`unknown` to `live` is the only way a session regains its stored liveness.
- **Actual:** 280 pass (P1). Test 1 sees `live` because `commitDelivery` already wrote it; test 4 checks only the return value of the second focus, not the stored row.
- **Impact:** a regression would leave a session shown as `unavailable` after Herdr is back and focus works.
- **Smallest fix:** in test 4, after the second focus, `expect(at.get(attempt.id).availability).toBe("live")`.

### INB011-R1-F2 — Minor — `get` silently caps attempts at 20 and can drop the delivered one

- **Where:** src/core/inbox.ts:583-587 (`LIMIT 20`); comment at inbox.ts:92-93.
- **Scenario:** item delivered, restored, then 21 fresh opens that are abandoned (P2).
- **Expected:** the delivered attempt (the one `focus` targets and whose session reference History "always shows") is in the summary, or the response says it is truncated.
- **Actual:** 20 newest abandoned attempts returned; delivered attempt absent; no count or truncation flag; `focus` still acts on the hidden attempt.
- **Impact:** rare in practice; the mod would lose the session reference for that item with no hint.
- **Smallest fix:** drop the limit (attempts per item are few), or always include succeeded attempts plus an `attempts_total` count.

### INB011-R1-F3 — Minor — blocking attempts get "after delivery" availability, unconditionally

- **Where:** src/worker/focus.ts:31-47 with target choice at focus.ts:22-24; alias recorded before start at src/worker/worker.ts:318.
- **Scenario:** user presses Focus (offered by next_actions for a blocking attempt with a pane) while the attempt is in `start_agent`: alias stored, agent not yet registered. Herdr answers `agent_not_found`.
- **Expected:** a starting or uncertain attempt is not declared `closed` (§13: "never assume nothing launched"; closure before delivery is only "established" by evidence).
- **Actual:** `availability = closed` and the error says "The session is no longer running in Herdr." Same before SessionStart reports a session -> `unknown`. Writes also carry no status/generation guard, so a focus reply that predates `commitDelivery` can overwrite its `live`, or two concurrent focus calls can leave the older observation stored. Status and delivery are unaffected; `commitDelivery` resets to `live`.
- **Impact:** the mod may show a session being launched, or a blocked one on screen, as closed; a narrow race can leave a delivered live session marked stale until the next focus.
- **Smallest fix:** record availability only when the target is `succeeded` (or map not-found on a blocking attempt to `unknown`), and make the write conditional, e.g. `UPDATE ... WHERE id = ? AND status = ?` with the status read before the Herdr call.

### INB011-R1-F4 — Minor — `unknown` still offers Focus, which can only fail

- **Where:** src/core/attempts.ts:660; test asserts it at test/unit/worker.test.ts (replaced-session test, `toContain("focus")`).
- **Scenario:** the alias now reports a different session (e.g. `/clear` in that pane). History keeps offering Focus.
- **Expected:** spec §4.2 step 9 offers Focus "while the verified live target exists".
- **Actual:** Focus stays offered for `unknown`; each press fails `AGENT_UNAVAILABLE` unless the exact session returns under that alias (e.g. `/resume` in the same pane). Defensible, but undocumented as a choice.
- **Impact:** a dead button for the common replaced case in the mod.
- **Smallest fix:** either drop `focus` for `unknown` too, or record the reason in the task notes / decisions so INB-013 labels it ("check again") rather than "Focus".

## Notes

- **N1** — `AttemptSummary.status` and `availability` are typed `string` (src/core/inbox.ts:98-105) while `AttemptStatus`/`Availability` unions exist; using them would give the mod a typed contract for free.
- **N2** — Test 5 ("newest first") sorts ids before comparing and runs on a fixed fake clock, so ordering is not verified; ties on `created_at` resolve by the random id suffix. Advance the clock between opens and assert order.
- **N3** — focus.ts:36-38 wraps any exception from `herdr.agent` (not only `HerdrError`) as retryable `HERDR_UNAVAILABLE` and records `unavailable`; before this change a non-Herdr error propagated. A programming bug would look like a Herdr outage.
- **N4** — "Availability is refreshed only by focus; reads never call Herdr" is a contract the mod relies on; worth one line in `docs/decisions.md`. Also: the `delivered_at` subquery filters `events` by `attempt_id` with no index on it (indexes are on producer and item); adding `e.item_id = a.item_id` would use `events_item`. Not a problem at current sizes. Pane-moved-but-same-session is treated as `unknown` and not focused (focus.ts:44), conservative and consistent with §10.3 "update stored live locations only after validation", which is not implemented here.
