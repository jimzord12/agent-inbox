## Findings

### INB006-R2-F1 — Material — a session id that stays missing after the receipt makes the worker loop forever

- **Where:** `src/worker/worker.ts:378-381` (the new `if (info && !session) { sleep; continue; }`), which jumps over the deadline check at `:384`.
- **Scenario (probe P2b):** the bridge accepts the prompt and captures a receipt; from then on Herdr's `agent get` reports the alias in the right pane with `agent_session: null` (Herdr loses or never regains session detection).
- **Expected:** "look again" until `receiptTimeoutMs`, then block (`RECEIPT_INVALID`, the receipt kept), as `verifyTarget` does.
- **Actual:** with `receiptTimeoutMs` 150 ms, after 3 s the attempt was still `in_progress` in `await_receipt`, lease held and renewed, 1 867 `agent get` calls made; only an abandon ended it. In production that is one `agent get` per second, forever, an item that reads "in progress" with no error, and `needsWorker` false (lease live), so nothing else picks it up.
- **Also:** no test pins the branch: deleting it leaves all tests green, and then a receipt plus a settled state with no session id would deliver without Herdr confirming the session.
- **Impact:** a silent, never-ending attempt and worker process, against "failures are loud and keep the item recoverable".
- **Smallest fix:** drop the `continue`; fall through to the deadline check, and require the session in the settle test (`if (info && session && seq > baseline && idle/done) return true`). Add a test: session stays null after the receipt → blocked at the timeout, no focus, receipt kept.

### INB006-R2-F2 — Minor — a stale `needsWorker` can start a worker that rewrites a block as `uncertain`

- **Where:** `src/cli/main.ts:130` with `src/worker/worker.ts:502-509` (`needsWorker`) and `:118-121` (`run` does not check the claimed row's status); `Attempts.claim` accepts `blocked` and `uncertain` rows.
- **Scenario (probes P1, P1b):** the first worker has not claimed yet when a second `open` (for example a double click in the mod) reads `needsWorker` = true and spawns another worker. If the first worker reaches a block and releases its lease before the second claims, the second claims the blocked attempt and walks it: phase rewritten, packet and settings rewritten, then `begin("start_agent")` finds the op and marks the attempt uncertain.
- **Expected:** a worker started for an unowned, untouched attempt does nothing when the attempt is no longer `in_progress` or has ops.
- **Actual:** P1: `blocked`/`AGENT_UNAVAILABLE` (alias in another pane) became `uncertain`/`DELIVERY_UNCERTAIN` "Step start_agent was already confirmed; reconcile before continuing." P1b: the worker's own dialog block became uncertain the same way. Zero Herdr calls from the second worker. With a changed profile or missing cwd, its preflight could even `fail` (revoke) a blocked attempt whose Claude is running, since all ops are resolved.
- **Impact:** a wrong diagnosis and a needless reconcile step; the window is narrow (the first worker must reach a block within the second's process start-up), so not Blocking.
- **Smallest fix:** in `Worker.run`, right after `claim`, release and return the view unless the row is `in_progress` with no ops (or give `claim` an `onlyInProgress` option for the fresh-worker path, leaving retry to INB-008). Add a test that runs a second worker on a blocked attempt and expects it unchanged.
