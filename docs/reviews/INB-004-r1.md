## Findings

### INB004-R1-F1: Unknown or null config keys silently fall back to the default socket (Minor)
- **File:** `src/core/config.ts:45`
- **Scenario:** `config.json` is `{"herdr":{"socketPath":"D:/x.sock"}}` (a typo), or `{"herdr":null}`.
- **Expected:** the config is refused as STORE_ERROR. Spec §10.2 says the Herdr endpoint is configured explicitly, with no fallback to another server, and the tests promise "invalid values are refused, never guessed".
- **Actual:** doctor reports the default `%APPDATA%\herdr\herdr.sock`. The user's intended server is ignored without a word.
- **Impact:** launches would go to the default Herdr server instead of the one the user tried to select. Low in practice today, because the owner runs one server.
- **Smallest fix:** reject unknown keys at the top level and under `herdr`, and reject a `herdr` that is not a plain object (null or an array). Add one test.

### INB004-R1-F2: Root-relative paths pass the "absolute" check (Minor)
- **Files:** `src/core/config.ts:48`, `src/core/config.ts:97` (and `src/core/profiles.ts:38`)
- **Scenario:** `setup-profiles --profile work=\Users --force`, or `config.json` `socket_path: "/x.sock"`.
- **Expected:** refused as not absolute. These paths have no drive letter.
- **Actual:** accepted and stored as `"\\Users"` or `"/x.sock"`. `win32.isAbsolute` treats a leading separator as absolute. The path then resolves against whatever drive is current when it is used, so a launch or the bridge could see a different folder than doctor checked.
- **Impact:** low. It needs a deliberate odd input, but it breaks the "absolute folders only" promise in AC2.
- **Smallest fix:** a shared `isFullyQualified(p)` helper that accepts only `X:\…` or a UNC `\\server\share` path. Use it in all three places.

### INB004-R1-F3: Trailing separator stored as given (Minor)
- **File:** `src/core/config.ts:104`
- **Scenario:** `--profile "work=C:\…\dir ü\wörk\"`.
- **Expected:** one canonical stored form.
- **Actual:** `claude_config_dir` is stored with the trailing `\`. The fingerprint is unaffected because `normalizeDir` strips it. But the raw string later becomes `CLAUDE_CONFIG_DIR` and may be compared or displayed as is. A trailing `\` before a closing quote is also a known Windows argv-quoting hazard if the value ever travels on a command line.
- **Smallest fix:** strip trailing separators (keeping a bare `C:\`) before storing.

### INB004-R1-F4: Empty or whitespace labels accepted (Minor)
- **File:** `src/core/config.ts:103`
- **Scenario:** `--label work=`.
- **Expected:** refused as INVALID_ARGUMENT, or fall back to the default label.
- **Actual:** `"label": ""` is written, and doctor and the UI would show a blank profile name.
- **Smallest fix:** trim the label and refuse it if empty.

### INB004-R1-N1: STATE_CONFLICT is checked before input validation (Note)
- **File:** `src/core/config.ts:85`
- With an existing `profiles.json`, `setup-profiles --profile work=relative` returns STATE_CONFLICT (exit 1) rather than INVALID_ARGUMENT (exit 2).
- Harmless, because either answer stops the write. Validating first would give a more useful first error.

### INB004-R1-N2: Overwrite check is check-then-rename (Note)
- **File:** `src/core/config.ts:85-113`
- Two parallel runs without `--force` could in theory both pass `existsSync`, and the later rename would win.
- Not reproduced: 6 parallel runs × 3 rounds, each time exactly one succeeded and five got STATE_CONFLICT.
- Acceptable for a one-time user command. If it is ever wanted, use `linkSync(tmp, path)` (which fails if the file exists) instead of `renameSync` when not forcing.
