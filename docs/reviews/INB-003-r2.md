## Findings

### INB003-R2-F1: Material. Two pre-effect codes can follow a dispatched or launched side effect

- **Where:** `src/herdr/adapter.ts:86-97` (`PRE_EFFECT_CODES`, `preEffect`), applied at `:148`.

**Part (a): `server_unavailable`.**
- **Binary evidence:** the 0.9.5 binary pairs this code with two messages:
  - "server is shutting down", including the literal envelope `{"error":{"code":"server_unavailable","message":"server is shutting down"}}`, in `src\server\headless.rs`;
  - "endpoint command ended without a response", in `src\server\client_commands.rs`.
- **What that means:** this code is sent by the server, so the request had reached it. The second message describes a command that was dispatched and whose reply was lost. That is spec §13's "Prompt send response lost: Submission is uncertain".
- **Scenario:** the worker calls `prompt(alias, handoff)`. Herdr is shutting down or doing a live handoff/upgrade, and the app loop drops the command after typing it.
- **Expected:** `outcome: "unknown"`.
- **Actual:** `outcome: "rejected"`. The worker may treat that as a definitive rejection and resubmit, which spec §13 says it may do only on proof of non-delivery. The same applies to `agent start`, where a Claude process may already be running in the pane.
- **Contrast:** `server_not_running` is raised by the CLI before connecting, so it is correctly pre-effect.

**Part (b): the `*_not_found` wildcard admits `agent_name_not_found` on `startAgent`.**
- **Binary evidence:** its message, "named agent … no longer owns the target terminal", sits in the same string cluster as the `agent start` outcomes: "timed out waiting for agent startup", `agent_kind_mismatch`, "agent process exited before becoming interactive", `agent_not_ready` and `cli:agent:start:timeout`.
- **Why it is post-launch by construction:** for `startAgent` the name is new. `agent_name_taken` covers a pre-existing name. So "the named agent no longer owns the terminal" can only be said after Herdr bound the name at launch.
- **Actual:** the adapter reports `rejected`, meaning nothing launched.
- **Expected:** `unknown`. The round-2 notes themselves say this code means "the occupant changed", which does not prove nothing happened.
- **Impact:** the worker may fail the attempt or relaunch, reusing the `--session-id`, while a launched or exited process and its pane exist. That is the exact case spec §13 forbids ("never assume nothing launched").

**Overall impact:** a false "nothing was done" on a mutating call. Reaching it is rare (server shutdown or upgrade mid-call, or an occupant change during startup), but it is the one direction the adapter exists to prevent, and the fix costs nothing. An `unknown` only makes the worker reconcile through `agent get` / `tab get`.

**Smallest fix:**
1. Remove `server_unavailable` from `PRE_EFFECT_CODES`. Reads still map it to `rejected`.
2. Replace the `_not_found` suffix wildcard with explicit target-resolution codes. The binary has `workspace_not_found`, `tab_not_found`, `pane_not_found`, `agent_pane_not_found`, `target_pane_not_found` and `agent_not_found`. Leave `agent_name_not_found` out, or at least treat it as `unknown` on `startAgent`.
3. Add two tests: `server_unavailable` on `prompt` gives unknown, and `agent_name_not_found` on `startAgent` gives unknown.
