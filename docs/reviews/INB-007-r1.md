## Findings

### INB007-R1-F1 — Material — worker-outlives-caller proved with a shell, not a Claude session

- **Where:** task AC #5; `docs/preflight.md` §7.1 row 5; INB-018 notes.
- **Scenario:** AC #5 says `agent-inbox open` is run from a Claude session in a test-workspace tab,
  then that tab is closed. The run used a shell tab (`tab-create-caller.json`, label "inb007 caller").
- **Expected vs actual:** expected the real caller shape the mod will have (a child of Claude Code's
  tool process, which can sit in a different process tree or job than a plain shell); actual a plain
  shell. The INB-018 note says it "may repeat … if that matters", which is not a filed check (AC #4).
- **Impact:** the case the product depends on (open from inside Claude, then close that tab) is still
  unproved; a Claude-specific kill of child processes would only surface in INB-018 or later.
- **Smallest fix:** one short live run in the same throwaway setup with a Claude session as the
  caller, or the owner's explicit acceptance of the shell substitute recorded on the task, plus an
  acceptance criterion (not a "may" note) on INB-018.

### INB007-R1-F2 — Minor — the forged-prompt refusal did not exercise the hash check

- **Where:** `docs/preflight.md` §7.1 row 2.
- **Scenario:** both forged prompts were sent after their attempts had succeeded; both transcripts
  show the reason `opening prompt refused (ATTEMPT_CLOSED)`.
- **Expected vs actual:** the row reads as if the wrong packet hash caused the refusal; the refusal
  came from the closed attempt, before any hash comparison.
- **Impact:** the live proof covers "a UserPromptSubmit block stops the prompt" (preflight point 2),
  not the live hash/attempt-id mismatch path on an open attempt; a reader could over-trust it.
- **Smallest fix:** reword: "refused because the attempt was already closed; the hash mismatch on an
  open attempt is covered by unit tests only".

### INB007-R1-F3 — Minor — "puts the refused text back in the input box" contradicts the transcript

- **Where:** `docs/preflight.md` §7.1 row 2, last sentence.
- **Scenario:** both blocked-prompt entries record `promptSubmitEnding: {kind: blocked_by_hook, promptKept: false}`.
- **Expected vs actual:** a claim backed by evidence; the only on-disk evidence says the prompt was not kept.
- **Impact:** low; matters later if the mod or a producer relies on the text staying (a second Enter

### INB007-R1-F4 — Minor — §7.1 row 1 omits the Herdr hook that AC #2 names, and the prod-guard argument is unrecorded

- **Where:** `docs/preflight.md` §7.1 row 1; task AC #2.
- **Scenario:** the row cites only the Stop summary (notify hook plus bridge). AC #2 names the
  production guard and the Herdr hook.
- **Expected vs actual:** evidence exists but is not written down: (a) Herdr's `agent_session` for
  both attempts has `source: herdr:claude`, which the profile's Herdr SessionStart hook reports, so
  that hook ran in the same SessionStart event in which the bridge's hook bound the attempt; the
  no-argv recording (`inb007-rec-ok`) shows Herdr gets the session only that way. (b) The bridge
  settings define only SessionStart, UserPromptSubmit and Stop; the profile's PreToolUse guard could
  only vanish if `--settings` replaced the profile's hooks wholesale, which (a) and the Stop summary
  disprove; both sessions made tool calls its matcher covers.
- **Impact:** AC #2 looks less proved than it is, and the Herdr-hook half is not recorded at all.
- **Smallest fix:** add (a) as observed and (b) as inferred, not observed, to row 1; then check AC #2
  with that wording, or leave the guard half explicitly unverified.
