## Lenses

1. **Product fit and wiring.** The tests drive the real `Worker`, `reconcile`, `Attempts`, `Inbox` and `safeHandle` against the fake Herdr runner. The bridge change reaches production code: `main.ts` stamps `startedAt` before it reads stdin, and `safeHandle` uses it. All four acceptance criteria have tests:
   - AC1: tab, start, prompt, receipt, and focus-before-commit, plus the case "before the tab answer was recorded".
   - AC2: the lost-prompt test.
   - AC3: the busy-store and VACUUM INTO restore tests.
   - AC4: the max_page_count test.
   The three carried items (INB-005 r3 N2, INB-008 retry after focus, INB-009 r3 F1 and N1) are each implemented and tested.
2. **Correctness and edge cases.** `written_at` and the rejection's `at` both come from the system clock on the same machine, in the same fixed-width ISO format, so comparing them as strings is sound. Taking `startedAt` before stdin is read is the conservative choice: an earlier stamp makes a receipt more likely to be dropped, never more likely to be replayed. One ordering was checked by reading the code: SessionStart S1 is busy, then a /clear SessionStart S2 is refused, then S1's retry binds. Bind then records S1's binding on an attempt that is already blocked. The block stays in place, and `last_rejection_json` is untouched, so the pending-receipt guard still holds. A later retry checks Herdr's session id, which is S2, and blocks. No delivery results.
3. **Data integrity (lead).** Every crash case ends with exactly one tab, one start and one prompt. Delivery happens only with bound + accepted + receipt + focused. Reconcile makes no Herdr call. Every write is a single `inbox.write` transaction, so a tripped write leaves no partial row. The full-store test compares full snapshots of items, revisions, attempts, ops and events before and after the refused submit and open. Submission and open write no files outside the DB (`src/core` writes only config), so nothing is left half-written beside the DB either. Extra probes all came out safe:
   - P1: the receipt arrives after reconcile has marked the attempt uncertain. Retry delivers with 1 prompt.
   - P2: a crash between the Herdr focus and recording it. Reconcile marks uncertain. Retry refocuses (focus count 2) and delivers with 1 prompt.
   - P3: a crash after `beginOp(create_tab)` but before the tab call. The attempt stays uncertain and no tab exists.
   - P4: a crash at `beginOp(dispatch_prompt)` itself. Retry sends the prompt for the first time and delivers.
4. **Contracts and privacy.** The new `STORE_ERROR` keeps the envelope shape: `{reason:"full"}` with `retryable:false`. The spec's code list does not name STORE_ERROR, but that code already existed before this change. Privacy: none found.
5. **Tests and evidence (lead).**
   - **Crash fidelity.** The spy wraps every worker-side `Attempts` write. P5 confirmed that, in all five cases, the dead worker makes zero Herdr calls after the trip point. Its own cleanup (`crashed()` → markUncertain or fail, then `release`, `renew`) runs, but every write it attempts throws. So the store holds exactly what a killed process would leave, and the lease lapses on the fake clock. The bridge's methods (`bind`, `acceptPrompt`, `captureReceipt`) are not wrapped, which is correct: the bridge is a different process and keeps running.
   - **Trip points.** Each sits on the adverse side of its boundary: after the effect, before it is recorded (`finishOp(..., confirmed)`, or `recordLayout(tab_id)`), or after `finishOp(focus)` and before `commitDelivery`.
   - **Deletion probes.** 17 mutations were run; 14 are caught by the suite.
     - Caught by `faults.test.ts` itself: reconcile never commits, reconcile never marks uncertain, the submit resend guard, the retry focus-confirmed branch, observeStart, the SQLITE_FULL mapping, the SessionStart retry, the startedAt stamp, and the busy-Stop non-receipt guard.
     - Caught only by older suites: the reconcile no-op skip, the orphan-tab path, needsWorker, the rejection-time guard, and the `crashed()` behaviour.
     - Survived the whole suite: the reconcile lease check (redundant: `claim` refuses a live lease), reconcile committing on focus alone (redundant: `commitDelivery` re-checks the evidence), and the `begin()` already-recorded guard (see F1).
   - **max_page_count as a stand-in for a full disk.** It produces the same `SQLITE_FULL` and the same rollback. SQLite's Windows VFS maps ERROR_DISK_FULL and ERROR_HANDLE_DISK_FULL to SQLITE_FULL. What it does not reproduce: a full disk hitting the WAL or shm file or a checkpoint, which can surface as `SQLITE_IOERR_*` (see N2). The author's notes state this limit.
6. **Failure handling (bridge changes).** Both changes are bounded and silent, and neither blocks. A SessionStart retry under a real lock took about 4.4 s (P7), and the worst case (an open wait plus a write wait, twice) is about 8 s. That is inside the 15 s settings timeout, and the 10 s stdin timer cannot fire during the synchronous handler. If the store is still busy on the second try, the hook returns `{exitCode:0}` and records nothing (P6). The worker's bind timeout then blocks the attempt, which stays recoverable. A retried SessionStart sends the same input through the same `bind` checks, so it cannot bind a session the first try would have refused. An S1-after-S2 inversion is covered under lens 2.
7. **Simplicity and ownership.** The changes are small and sit in their owning modules. Core is still the only DB writer. Nothing outside the task's scope was added.
8. **Repository and docs.** The commit subject follows the convention. The task notes record the method, the cases, what is not done (real ENOSPC or an OS-level crash), and the decision on N1 (retry once). There is no decisions.md entry for N1 (see F2).

## Findings

### INB010-R1-F1: Minor. The `begin()` already-recorded guard has no test that fails without it

- **Where:** `src/worker/worker.ts:522-527` (`begin`); `test/unit/faults.test.ts`.
- **Scenario:** A worker crashes after `start_agent` was performed. Then a plain (non-retry) worker claims the lapsed attempt before reconcile has marked it uncertain.
- **Expected vs actual:** Expected: some test fails if `if (prev === null) return true;` is replaced by `return true;`. Actual: the whole suite passes with that mutation. Probe P8 shows what the mutation does: the plain worker starts Claude a second time and sends the prompt (starts 2, then succeeded). With the guard in place, the same probe ends uncertain with starts 1.
- **Impact:** Low today, because `open` starts a worker only when `needsWorker` is true (no ops recorded). But this guard is the worker's last defence against blind replay, and nothing pins it.
- **Smallest fix:** Add one fault test: crash at `finishing("start_agent")`, run `worker(fake, id, false)` with no reconcile in between, and expect `uncertain` with 1 agent start and 0 prompts.

### INB010-R1-F2: Minor. The N1 decision is not in decisions.md

- **Where:** `docs/decisions.md`; task INB-010 notes.
- **Scenario:** The INB-009 r3 N1 note asked whether the worker's bind timeout is enough. The author settled it with "retry SessionStart once".
- **Expected vs actual:** Expected: a one-line decision with its bound (about 8 s worst case, inside the 15 s hook timeout). Actual: it is recorded only in the task notes and a code comment.
- **Impact:** A later change to the hook timeouts could break the bound without anyone noticing.
- **Smallest fix:** Append one line to `docs/decisions.md`.

## Notes

- **N1.** Three guards are redundant pairs:
  - reconcile's `leaseLive` with `claim`'s live-lease refusal;
  - reconcile's evidence condition with `commitDelivery`'s own checks;
  - the retry orphan-tab path with `begin()`.
  Deleting one side alone is not caught. That is acceptable defence in depth, not a defect.
- **N2.** `fromStoreError` maps only `SQLITE_FULL` to the "full" message. A full disk that surfaces as `SQLITE_IOERR_WRITE` or `SQLITE_IOERR_SHMSIZE` would show the generic "Store error (...)". Consider adding those codes when the live runs give evidence.
- **N3.** In the fake runner, the receipt is captured during `agent prompt`, so the "after prompt" and "after receipt" cases both have the receipt in place before the crash. Probe P1 confirms the other order (receipt after the crash, and after reconcile) also delivers safely. One test for it would document that.
- **N4.** A crash between the Herdr focus and `finishOp(focus)` (probe P2) leads to a second focus on retry. This is allowed: focus carries no context.
- **N5.** On a full store, Stop's `captureReceipt` failure is not saved aside (only busy is), so the receipt is lost and the attempt blocks at the receipt timeout. It stays recoverable, and the behaviour is acceptable.
