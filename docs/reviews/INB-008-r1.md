# INB-008 review, round 1: retry and abandon

## Snapshot

- Unit: INB-008 "Add retry and abandon with reconcile-first behaviour" (AC #1-#3, carried notes from INB-002 N2 and INB-006 r1 N3/N5, r3 N1).
- Base: 3149653 (the commit before head). Head: 5164c31.
- Changed: src/worker/worker.ts, src/worker/main.ts, src/cli/main.ts, src/core/attempts.ts, test/unit/{worker,cli,attempts}.test.ts, two backlog task files.
- Reviewer checks on head: `bun run typecheck` clean; `bun run test` 232 pass, 0 fail.
- Reviewer probes: ten in-process scenarios with the fake Herdr runner (P1-P10) and fifteen deletion probes (M1-M11), all run in a scratch copy of head with its own temp inbox home. No real Herdr, no Claude, nothing under test/e2e/.

## Verdict

**FINDINGS.** One Material finding (INB008-R1-F1): retry lifts a profile refusal recorded by the bridge, and nothing checks the profile again. Three Minor findings and three Notes. The acceptance criteria are met and the lead-lens guarantees hold: retry never sends the opening prompt again after a recorded dispatch, never starts Claude twice, and never commits for a session other than the bound one.

## Lenses

1. **Product fit and wiring.** `agent-inbox retry` starts `worker/main.ts <id> --retry` unless a live lease holds the attempt. `abandon` calls `Attempts.abandon`. The worker resumes on retry and reconciles each op in order. AC #1 (focus refused, then retry refocuses and commits), AC #2 (no second prompt) and AC #3 (abandon releases the item, keeps session_uuid, revokes the capability) are each covered by a test, and the tests pass. INB-006 r3 N1 (the new settle-timeout message) is in place and tested.
2. **Correctness and edge cases.** A second retry while a worker holds the lease is refused by the CLI's lease check and by `claim`. A retry of an in-progress attempt whose lease lapsed runs the reconcile walk; this overlaps INB-009 but is safe. A retry of an uncertain focus (the focus answer timed out) refocuses and delivers (P6). One race: the worker reads the status before `resume`, but `resume` is unconditional, so a bridge block that lands in between is lifted (Note F7).
3. **Data integrity (lead).**
   - The prompt is never sent twice. The only resend path needs `prompt_state = rejected`, and `clearFailedOp` enforces that again. An uncertain, started or accepted dispatch is never resent (tests, P10, M3b).
   - Claude is never started twice (tests, P9).
   - Every commit goes through `verifyTarget` (Herdr reports the bound session_uuid in the recorded pane) and through `awaitReceipt` (a settle newer than the recorded baseline).
   - INB-002 N2 holds (P1): the session is replaced and the attempt blocked, the original session then sends a late valid receipt, and retry delivers with one prompt. When Herdr reports the replacement session instead, retry blocks (P2).
   - Exception: a profile refusal from the bridge, once lifted by retry, is never checked again (F1).
   - Minor: the dispatch op can stay `started` on a delivered attempt (F3).
4. **Contracts and privacy.** The CLI shapes match spec §8 (`retry ATTEMPT`, `abandon ATTEMPT`, JSON envelope, STATE_CONFLICT on a closed attempt). The worker accepts the `--retry` argument. Privacy check of the diff: none found.
5. **Tests and evidence.** These deletions each fail a test: the submit guard (M3, M3b), the recorded baseline (M4), the `finishOp` detail merge (M5), the CLI lease check (M7), `observeStart` (M8), the non-retry release (M9), the settle message (M10) and the confirmed-start skip (M11). These deletions fail no test: the uncertain-focus redo (M6b), the own-session check in `observeStart` (M8b), the preflight skip (M1), the createLayout retry block (M2) and the CLI revoked check (M7b, which is redundant because a revoked attempt is always failed). M6, the confirmed-focus commit, is untested by the author's own note and carried to INB-010. No test covers N2 (F4).
6. **Failure handling (lead).** Each op state against each attempt status:
   - create_tab started or uncertain: stays uncertain.
   - start_agent started or uncertain: observed; the walk continues only when Herdr shows the attempt's own session.
   - dispatch: accepted, uncertain or started is never resent.
   - focus: failed, started or uncertain is redone; confirmed is committed.
   - Abandon during a retry fences the worker: the attempt ends failed and revoked, the item stays Active, and nothing is committed (P5).

   Weak spots: when the retry worker cannot be spawned, the attempt can end failed or hold a stray lease (F2), and some stopped states give unclear messages (F5).
7. **Simplicity and ownership.** Core remains the only database writer, and the CLI only reads the row. The CLI's lease-live expression copies the one in `needsWorker`; this is taste, not a finding. No unasked scope.
8. **Repository and docs.** The task notes and the INB-010 carry-over are coherent. One task note is contradicted by P4 ("can be retried, but nothing is sent: the walk stops at the binding or identity check"); see F1. No decision entry is needed.

## Findings

### INB008-R1-F1 (Material): retry lifts the bridge's profile refusal; nothing checks the profile again

- **Where:** src/worker/worker.ts:141 (`this.at.resume(this.attemptId, gen)`, no code filter); src/core/attempts.ts:405-411 (`resume` clears `last_rejection_json`); src/core/attempts.ts:469-483 (a refused bind keeps an earlier `binding_json`); `toView` offers `retry` on every blocked attempt.
- **Scenario A (realistic, P7):** the session starts under the wrong Claude configuration. The bridge blocks with PROFILE_LAUNCH_UNSUPPORTED and records the reason. The owner presses retry, which the next actions offer. Retry lifts the block, waits the bind timeout and blocks with RECEIPT_INVALID "The session never reported its startup to the inbox bridge.". `last_rejection` is now null.
- **Scenario B (contrived, P4):** binding succeeds. A later SessionStart for the same session id reports a different config folder and an auth-affecting variable, and the bridge blocks with PROFILE_LAUNCH_UNSUPPORTED. A valid receipt from that session follows. Retry then commits `succeeded` and archives the item as delivered.
- **Expected:** a profile verdict from the bridge stays in force until a fresh, valid binding replaces it. Retry of such an attempt either refuses, telling the owner to abandon and open again, or keeps the block with its original reason (spec §11 "Never substitute another account"; §9.1 step 2).
- **Actual:** A loses the true cause and shows a false one. B delivers although the latest evidence says the profile is wrong. The author's task note claims retry "stops at the binding or identity check", and B shows that it does not.
- **Impact:** with A, the owner cannot see why the attempt is stuck. B is a delivered state whose profile evidence was overturned (low reachability: the user must restart the session with the attempt's settings).
- **Smallest fix:** in retry mode, do not lift a PROFILE_LAUNCH_UNSUPPORTED block: the worker releases and leaves it, and the CLI returns STATE_CONFLICT "abandon and open again". Alternatively, a refused bind clears `binding_json`, so `verifyTarget` waits for a fresh good bind. Also pass the observed `error_code` as `onlyCode` to `resume` (see F7). Add a test for scenario A, and correct the task note.

### INB008-R1-F2 (Minor): a retry spawn failure runs `failBeforeStart` on an attempt that already has side effects

- **Where:** src/cli/main.ts:213-225 (the `startWorker` catch); src/worker/worker.ts:584-588.
- **Scenario:** `agent-inbox retry` on a blocked attempt whose tab and Claude session exist (ops confirmed, prompt none), and `spawn` throws.
- **Expected:** the attempt stays blocked, and the CLI reports that the worker could not start.
- **Actual:** `failBeforeStart` claims the attempt and fails it terminally, which revokes the capability while a live bound session exists. Its comment says "nothing external has happened yet", which is false on this path. When ops are unresolved, `fail` throws STATE_CONFLICT instead and leaves a 60 s lease held by `cli:<pid>`. During that minute every retry answers `started: false`.
- **Impact:** a rare local failure turns a recoverable attempt into a failed one, or leaves a confusing error and a stuck lease.
- **Smallest fix:** on the retry path, do not call `failBeforeStart`. Throw an INTERNAL error and leave the attempt untouched. Alternatively, make `failBeforeStart` apply only when no op is recorded, and release its claim in a `finally`.

### INB008-R1-F3 (Minor): the dispatch op stays `started` on a delivered attempt

- **Where:** src/worker/worker.ts:433.
- **Scenario (P3):** the worker crashes after Herdr typed the prompt but before `finishOp`. The bridge accepts the prompt, and a retry delivers.
- **Expected:** the ops show dispatch_prompt `confirmed`, as they do for an uncertain dispatch.
- **Actual:** the ops end as `[create_tab confirmed, start_agent confirmed, dispatch_prompt started, focus confirmed]` while the attempt is `succeeded`.
- **Impact:** the op log contradicts the outcome, and an INB-009 reconcile scanning open ops could mistake it for unfinished work.
- **Smallest fix:** confirm on acceptance when the op is `started` or `uncertain`; `finishOp` already allows both.

### INB008-R1-F4 (Minor): new guards and a carried requirement without tests

- **Where:** test/unit/worker.test.ts, the retry describe block.
- **Scenario:** each of these deletions leaves all tests passing:
  - M6b: the uncertain or started focus that is redone (src/worker/worker.ts:475). This is the focus-timeout variant of AC #1. Without the branch, retry turns the attempt uncertain instead of delivering, as P6 shows.
  - M8b: the own-session and pane check in `observeStart` (line 324).
  - M1: the preflight skip (line 194).
  - INB-002 N2 is a carried requirement and has no test; P1 shows that it works.
- **Expected:** a test fails when each guard is deleted.
- **Impact:** regressions in the AC #1 variant and in N2 would pass the gate.
- **Smallest fix:** add tests for (a) a focus timeout followed by a retry that delivers with one more focus, (b) the N2 flow from P1, and (c) Herdr showing a different session after a lost start answer, where retry ends uncertain without focusing or blocking AGENT_BLOCKED.

### INB008-R1-F5 (Note): some retry outcomes are permanent or poorly worded

- create_tab or start_agent `started` without a recorded result, and a dispatch `started` without acceptance, leave the attempt uncertain on every retry until it is abandoned (P9, P10). This matches spec §13 and the INB-009 scope.
- `observeStart` reads Herdr once, so a session id that is only late leaves the attempt uncertain. That is conservative.
- A retry on an uncertain create_tab whose cwd has since vanished ends with "The worker stopped unexpectedly: Unresolved external steps: create_tab…" (P8). The cwd cause is lost, because preflight's `fail` throws before the create_tab check runs.

### INB008-R1-F6 (Note): the new settle message can be inaccurate

- "Claude acknowledged, but Herdr never reported its session id" is also shown when `verifyTarget` saw the id and only `awaitReceipt` lost it (worker.ts:428-454).
- "…did not report its session id after acknowledging" would be accurate in both cases.

### INB008-R1-F7 (Note): the status read and `resume` are not one transaction

- worker.ts:135-141 reads the status, then `resume` lifts whatever block is present.
- A bridge block that lands between the two is lifted. Today this is safe for a replaced session, because the refused bind clears the receipt candidate.
- Passing the read `error_code` as `onlyCode` closes the gap, and fits with F1.
