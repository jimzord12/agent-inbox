## Findings

### INB006-R1-F1 — Material — the dialog watch resumes an attempt the bridge blocked

- **Where:** `src/worker/worker.ts:284-294` (`watchBlockedStart`), with `Attempts.resume` (`src/core/attempts.ts:399-403`).
- **Scenario:** Claude starts behind a trust dialog (`agent_not_ready`); the worker blocks with `AGENT_BLOCKED` and polls. The user answers; SessionStart runs and the bridge refuses the binding (wrong config folder, auth variables, or a different session) and sets the attempt `blocked` with its own code. The worker only checks `status !== "blocked"`, so it still sees "blocked", reads a ready agent, and calls `resume`.
- **Expected:** the worker continues only its own `AGENT_BLOCKED`; a block set by the bridge stays until an explicit user action (the core's own rule: "a block … needs an explicit resume first").
- **Actual (probe P1):** bridge result `PROFILE_LAUNCH_UNSUPPORTED`, status `blocked`; after the worker ran, status `blocked` with `RECEIPT_INVALID` "The session never reported its startup to the inbox bridge.", `last_rejection` = null. The real cause is gone. If the bridge's block came after an earlier valid bind (session replaced), `binding_json` is kept, so only Herdr's session report then stands between the resumed worker and a dispatch.
- **Impact:** a safety verdict of the bridge is silently overridden and the owner is told the wrong reason (a profile problem shows as "never reported its startup"). No false delivery was reachable in the probe.
- **Smallest fix:** in the loop, stop (`throw new Stop()`) unless `row.status === "blocked" && row.error_code === "AGENT_BLOCKED"` (or record a worker-owned marker when blocking and check it); add a test where the bridge blocks during the watch.

### INB006-R1-F2 — Material — the "new settled state" guard of AC #4 is not pinned by any test

- **Where:** `src/worker/worker.ts:367`; `test/unit/worker.test.ts:231-237`.
- **Scenario:** delete either `(info.state_change_seq ?? -1) > baseline` or the `idle/done` status check.
- **Expected:** a test fails; the test named "the startup idle does not count" should fail when the seq guard is removed.
- **Actual:** 27/27 pass in both mutations. The test sets `agent_status = "working"` and leaves the seq unchanged, so either guard alone blocks it.
- **Impact:** the guard that stops the startup idle from counting as the settled opening turn (spec §9.1 step 6) can regress unnoticed.
- **Smallest fix:** two cases: receipt + `idle` + unchanged seq → blocked (probe P2 shows the current code does this); receipt + seq increased + `working` → blocked.

### INB006-R1-F3 — Material — identity re-checks can be deleted with all tests green

- **Where:** `src/worker/worker.ts:309`, `:312`, `:363-366`, `:288`; `src/worker/focus.ts:61`.
- **Scenario:** each mutation removed one of: the pane check before dispatch; the session/pane re-check before settling; the "alias gone" block; the blocked-watch status check; the pane check in `focusItem`.
- **Expected:** at least one test fails per guard (lens 5; spec §10.3 revalidation).
- **Actual:** 27/27 pass for every one.
- **Impact:** the checks that keep context and delivery on the attempt's own pane and session have no regression protection.
- **Smallest fix:** fake cases: alias reported in another pane before dispatch → blocked, no prompt; session or pane changes after the receipt → blocked, no focus, item Active; agent gone before dispatch → blocked; `focusItem` with the alias in another pane → refused; plus the F1 test.

### INB006-R1-F4 — Minor — an unexpected error overwrites the bridge's block with a generic uncertainty

- **Where:** `src/worker/worker.ts:434-443` (`crashed`).
- **Scenario (probe P4):** the bridge blocks the attempt (session replaced) between the receipt check and `commitDelivery`. Focus is confirmed, `commitDelivery` throws `STATE_CONFLICT`, and `crashed` calls `markUncertain`.
- **Expected:** a block already set by the bridge is kept; `crashed` marks uncertain only an `in_progress` attempt, and only when an op is open or the prompt is unsettled.
- **Actual:** `uncertain` / `DELIVERY_UNCERTAIN` "The worker stopped unexpectedly: The attempt is blocked…". The bridge's code is lost. An error before any side effect (e.g. a disk error in preflight) also becomes `uncertain` instead of `failed`.
- **Impact:** a wrong diagnosis, and a needless reconcile step.
- **Smallest fix:** in `crashed`, re-read the row; leave it if not `in_progress`; otherwise mark uncertain only when an op is `started`/`uncertain` or the prompt is `started`/`uncertain`/`accepted`, else `fail`.

### INB006-R1-F5 — Minor — a transient missing session report after the receipt blocks the attempt

- **Where:** `src/worker/worker.ts:364`.
- **Scenario (probe P3):** after the receipt, one `agent get` shows `agent_session: null` (Herdr re-detecting during or after the turn); the next read would show the right session settled.
- **Expected:** as in `verifyTarget`, a missing session is "look again"; only a different session or pane blocks.
- **Actual:** blocked `AGENT_UNAVAILABLE` "Herdr no longer reports the attempt's session in its pane." Fail-closed; the item stays Active until a retry.
- **Impact:** a spurious block on a good handoff, which the owner must clear by hand (no retry command until INB-008).
- **Smallest fix:** block only when `agent_session?.value` is present and different, or `pane_id` differs; keep polling on a null session.

### INB006-R1-F6 — Minor — a worker that never claims leaves a silent `in_progress` attempt

- **Where:** `src/cli/main.ts:190-203` (`child.on("error", () => {})`), `src/worker/main.ts:26` (`claim` outside any handler).
- **Scenario:** the spawn fails asynchronously, or the worker exits before `claim` (e.g. `STORE_BUSY` or a bad script path in an installed build).
- **Expected:** a loud failure: the attempt ends `failed` with a code, as `failBeforeStart` does for synchronous errors.
- **Actual:** the attempt stays `in_progress` with no lease, phase `preflight`, no error. A second `open` reuses it and starts no worker. Its only next actions are `view` and `abandon`.
- **Impact:** the owner sees "in progress" forever; recovery depends on INB-008/009.
- **Smallest fix:** in `worker/main.ts`, wrap `run` so a failure before `claim` calls `failBeforeStart`; optionally have the CLI wait about 200 ms for the child's `spawn`/`error` event before replying.

## Notes

- **N1:** two first-ever opens racing both read no workspace id and both create an inbox workspace; the last write to `herdr-state.json` wins and the other is orphaned (`worker.ts:213-216`). Rare and harmless to delivery.
- **N2:** a failing `writeWorkspaceId` after a successful create is reported as "Herdr is not reachable" (`worker.ts:216-219`).
- **N3:** the dispatch baseline is held in memory only (it is also written to the op detail). A retry worker (INB-008) must read it from `detail_json`, or it has no baseline.
- **N4:** `docs/preflight.md` §3 names `completion_seq` as the signal for a new idle; the worker uses `state_change_seq`. Either works with the receipt requirement; align the doc or the code in INB-007.
- **N5:** `next_actions` offers `retry` for blocked/uncertain attempts before a `retry` command exists (INB-008).
- **N6:** `open --profile P` on a reused attempt silently returns the existing attempt with its old profile; the caller can see it only by comparing `profile_id`.
- **N7:** `tabLabel` cuts by UTF-16 units and can split a surrogate pair at character 23; the label is cosmetic.
- **N8:** `worker/main.ts:22` maps every config error to `HERDR_UNAVAILABLE` through a ternary whose two branches are equal; a broken `config.json` would read better as its own `STORE_ERROR`.
- **N9:** the dialog-blocked start is focused by alias without an identity read first; the alias was created moments before by this attempt and focus carries no context, so the risk is small.
- Unverified here, as the author says (INB-007): real `agent start`/`prompt`/`focus` answers, whether Herdr registers the alias before `agent_not_ready`, `state_change_seq` behaviour, and the detached worker surviving its caller's tab.
