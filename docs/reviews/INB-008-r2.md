## Findings

### INB008-R2-F1 (Minor): the worker's own later block, and a later bridge bind, can still overwrite a profile verdict

- **Where:**
  - src/core/attempts.ts:598-622: `transition` writes status and code whatever the current status is.
  - src/worker/worker.ts:338: `watchBlockedStart` blocks AGENT_BLOCKED unconditionally.
  - src/worker/worker.ts:531-538: `end()` acts on a row read before an awaited Herdr call.
  - src/core/attempts.ts:469-479: a later refused bind replaces the code.
- **Scenarios (probes on head):**
  - **Q2.** SessionStart reports the wrong profile, then `agent start` answers `agent_not_ready` (a dialog). `watchBlockedStart` overwrites the verdict with AGENT_BLOCKED. Once the dialog clears, it resumes (which erases `last_rejection`) and ends RECEIPT_INVALID "The session never reported its startup to the inbox bridge." No retry is needed for this.
  - **Q1.** The wrong-profile SessionStart lands during the last `agent get` before the bind deadline. The worker's stale read ends RECEIPT_INVALID over it. CLI retry is then allowed, and it erases `last_rejection`.
  - **Q6 (contrived).** Profile refusal after bind, then a SessionStart with another session id. RECEIPT_INVALID replaces the profile code. A late valid receipt from the original session then makes retry deliver.
- **Expected:** a PROFILE_LAUNCH_UNSUPPORTED verdict stays until the attempt is abandoned (round 1 F1 expectation; the comment at worker.ts:349-350 says the same).
- **Actual:** the verdict and its diagnostic are replaced by a misleading RECEIPT_INVALID, and the retry refusal no longer applies.
- **Impact:**
  - Q1 and Q2 never deliver, because a first-start refusal records no binding. The owner sees a false cause, and retries cannot help.
  - Q2 needs Claude to show a dialog after SessionStart has run (not checked live).
  - Q1 needs a race at the deadline.
  - Q6 needs round 1's contrived scenario B plus a session change.
- **Smallest fix:**
  - Make `block`/`markUncertain` a no-op (return false) when the row is no longer `in_progress`, and have `watchBlockedStart` and `end()` treat that as Stop.
  - In `bind`, keep an existing PROFILE_LAUNCH_UNSUPPORTED code rather than downgrading it.
  - Add a test with Q2's hooks: `onStart` binds the wrong profile and returns `agent_not_ready`.

### INB008-R2-F2 (Minor): the read-to-resume guard (round 1 F7) has no test

- **Where:** src/worker/worker.ts:140 (`error_code ?? undefined` passed as `onlyCode`).
- **Scenario:** N2 drops `onlyCode`, so `resume` lifts any block, and all 239 tests still pass.
- **Expected:** a test fails, because the task note claims this guard.
- **Impact:** a regression would silently reopen the race in which a bridge verdict landing between the read and the resume is lifted.
- **Smallest fix:** a worker test that binds the wrong profile between the claim and the resume. Probe Q5 does it by wrapping `Attempts.prototype.resume` once. It then expects `run()` to return null and the code to stay PROFILE_LAUNCH_UNSUPPORTED.

### INB008-R2-F4 (Note): two fixes are not pinned by a test

- **N4:** the retry spawn-failure path (round 1 F2) fails no test when reverted. A synchronous `spawn` throw is hard to provoke, so code reading is acceptable here.
