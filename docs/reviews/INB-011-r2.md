## Findings

### INB011-R2-F1 — Minor — focus on a still-starting attempt still tells the caller "closed"

- **Where:** src/worker/focus.ts:41-43 (and 45-47 for `unknown`); setAvailability's return value unused at focus.ts:31.
- **Scenario:** an uncertain or blocked attempt whose agent is not (yet) registered under its alias; user runs `focus` (offered by next_actions for blocking attempts) (P1).
- **Expected:** round 1 F3's point was that a starting/uncertain attempt is not declared closed (§13: "never assume nothing launched"). The stored value is now correct.
- **Actual:** the error still says "The session is no longer running in Herdr." with `details.availability: "closed"`, while the stored availability stays `unknown`. The CLI JSON and the stored row disagree.
- **Impact:** the mod (INB-013) or a script reading the error may show a launching session as closed; low, since the stored value and next_actions are right.
- **Smallest fix:** for a non-succeeded target, report the attempt's own availability (or omit it) and use a neutral message ("No agent is registered under this attempt's alias yet."); or branch on `seen(...)` returning false.

## Notes

- **N1** — The status guard is checked at write time, not against the status read before the Herdr call; the code comment at attempts.ts:326-327 ("a late answer cannot land on the wrong state") overclaims. P2 shows a focus begun on a blocking attempt can write `closed` onto an attempt that became `succeeded` during the call. Realistically near-impossible (delivery needs the agent present, and the answer is written immediately after it returns), and the next focus corrects it. Passing the expected status into the UPDATE would close it fully.
- **N2** — The always-listed window is "newest 20 of all attempts, plus any older delivered or unfinished", not "the newest 20 others" (inbox.ts:588 comment, task notes). With delivered/unfinished attempts among the newest, fewer than 20 failed ones show (P4). Behaviour is fine; wording only.
- **N3** — Deleting both `if (!(err instanceof HerdrError)) throw err;` lines fails no test. The fake runner cannot reach them because the adapter turns every runner exception into a `HerdrError` (P3); they only guard adapter-internal bugs. Acceptable without a test; noted for completeness.
- **N4** — Ties on `created_at` (same clock tick, P4) order by the random id suffix, so "newest first" is only meaningful across distinct timestamps; the real clock makes ties rare. No action needed.
