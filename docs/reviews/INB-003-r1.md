**Snapshot:** base `c731c34`, head `675e7c2` (one commit). Files: `src/herdr/adapter.ts`, `test/unit/herdr.test.ts`, `test/unit/fixtures/herdr.ts`, the task file.

## Verdict: FINDINGS

There is one Material finding (F1): Herdr error codes that arrive after Claude has already launched or input has already been typed are reported as `rejected`. Everything else is Minor or Note.

## Lenses

**1. Product fit and wiring.** No caller yet; INB-006 will be the worker. The API covers what spec §10 needs:
- explicit workspace by configured id;
- `tab create` with workspace, cwd, label, env and `--no-focus`, returning the root pane;
- `agent start` with name, pane and pass-through args;
- `agent get` with `agent_session`, `completion_seq` and `state_change_seq` for binding and the settle check;
- `agent list`;
- `prompt` without `--wait`;
- `focus` by alias.

AC1 is met. AC2 is met as written, but see F1. AC3 is partly met, see F2.

**2. Correctness and edge cases.**
- Argv matches the 0.9.5 usage lines: `agent start <NAME> --kind --pane --timeout -- args`, `agent prompt <TARGET> <TEXT>`, `tab create --env KEY=VALUE`, `--no-focus`.
- Windows: CRLF is handled (trim per line). Paths with spaces and Unicode pass as single argv items (tested). Stdin is ignored.
- The wall-clock timeout for `startAgent` is Herdr's timeout + 10 s, so Herdr's own `timeout` answer normally arrives first.
- See F3 (workspace id reuse) and N2 (`agent_name_not_found` collapsed to null).

**3. Data integrity.** n/a for direct writes: the adapter never touches the store. Its only effect on integrity is through the outcome it hands the worker, and that is covered by F1.

**4. Contracts and privacy (lead).**
- Envelopes match the schema: `success_response` is `{id, result}` and `error_response` is `{id, error:{code,message}}`, with free-string codes and no enum.
- Result types match the schema: `agent_started = {agent, argv}`, `agent_prompted = {agent}`, `agent_list = {agents}`, `ok = {type}`.
- `HERDR_SOCKET_PATH` is a variable the binary reads.
- The variables actually set in a Herdr pane are `HERDR_PANE_ID`, `HERDR_TAB_ID`, `HERDR_WORKSPACE_ID`, `HERDR_ENV`, `HERDR_SOCKET_PATH` and `HERDR_BIN_PATH`. The first four are dropped and the socket is overridden.
- The binary also reads `HERDR_SESSION`, `HERDR_CLIENT_SOCKET_PATH` and `HERDR_ACTIVE_*`. None of these is set in a pane today; see N3.
- Privacy: none found.

**5. Tests and evidence.**
- Deleting the stderr parsing, the env scrubbing, the ambiguous-code set or the kill timer would each fail a test.
- Mocks sit only at the process boundary, and real-process runner tests use Bun as a stand-in.
- The fixture header honestly labels recorded vs schema-built answers.
- Gap: no test for an `agent start` error after launch (F1). Unrecorded primitives: F2.

**6. Failure handling (lead).**
- Spawn failure gives `herdr_unavailable` / rejected. Correct: nothing ran.
- Own timer kill, Herdr `timeout`, and an unreadable answer on either stream with any exit code all give unknown. Correct, and conservative.
- `agent_blocked` on prompt gives rejected. Correct: Herdr's help says it is "rejected … before any input is sent".
- The author's design choice is sound. Putting `timeout` in the ambiguous set is right: the binary's own message for `agent start` is "timed out waiting for agent startup", and the server-wide "timed out waiting for app response" also uses `timeout`. `agent_prompt_stalled` can only come with `--wait`, which the adapter never sends (N1).
- The flaw is the default: every other code is treated as "nothing done". That is false for several `agent start` and prompt codes (F1).

**7. Simplicity and ownership.** Small, single module. No DB access, no unasked scope.

**8. Repository and docs.** The commit subject follows the convention. The task notes record the stderr envelope and the trailing-backslash cwd discovery. The fixture comment says "INB-007 records the real ones", but INB-007's acceptance criteria do not say so (F2).

## Findings

### INB003-R1-F1: Material. Post-launch `agent start` and prompt errors are reported as "rejected"

- **Where:** `src/herdr/adapter.ts:80-82`, `:127-130`.
- **Scenario:** The worker calls `startAgent` in a fresh throwaway folder. Claude starts and shows its folder-trust dialog. Herdr's own `agent start` documentation (text embedded in the 0.9.5 binary) says: "If the agent is blocked during startup, the command returns `agent_not_ready` immediately but keeps the name available for `agent read` and `agent send-keys`."
- **Expected:** Spec §10.2 and §13 say a blocked startup is marked blocked and its exact pane is focused, and the same attempt continues. A readiness failure is never assumed to mean nothing launched.
- **Actual:** `agent_not_ready` is not in `AMBIGUOUS_CODES`, so it surfaces as `outcome: "rejected"`, which the class doc defines as "nothing done".
- **Same problem with other codes from the binary.** Each of these can follow a launched or partly sent side effect but is also classed rejected:
  - `agent_kind_mismatch` ("expected …, detected …", so a process was started);
  - `agent_start_input_failed`, which suggests input was partly typed;
  - `agent_prompt_failed`, seen next to "pty actor closed";
  - the code behind "agent process exited before becoming interactive".
- **Impact:** A worker trusting the adapter's own contract treats the step as safely not done. It may then fail the attempt or launch again while a live, blocked Claude session holds the alias and the pane. That is a duplicate session, and the "focus the blocked pane" path is never taken. It is exactly the "never assume nothing launched" case.
- **Smallest fix:**
  1. Invert the default for side-effecting verbs (`agent start`, `agent prompt`, `tab create`, `workspace create`, `focus`). Classify as `rejected` only codes that Herdr documents as raised before the effect: `*_not_found`, `server_not_running`, `server_unavailable`, `agent_blocked`, `agent_name_taken`, `agent_pane_unavailable`, `agent_target_ambiguous`, `invalid_*`. Everything else becomes `unknown`.
  2. Optionally, map `agent_not_ready` to a distinct `blocked` outcome so the worker can focus the pane.
  3. Add a test for `agent_not_ready` on `startAgent`, and one for an unlisted code on a mutating call.

### INB003-R1-F2: Minor. AC3 is only partly backed by recorded JSON, and the follow-up is not tracked

- **Where:** `test/unit/fixtures/herdr.ts:1-4`, `:71-84`; `backlog/tasks/inb-007 - …md` acceptance criteria.
- **What is recorded:** workspace create, tab create, tab get, the not-found answers and `server_not_running`. Agent get is a recorded shape with replaced values.
- **What is schema-built:** agent start, prompt, list, focus and workspace get. The schema check holds (the result shapes match `success_response`), so the tests are sound against the contract. They are not "recorded Herdr JSON" as AC3 says.
- **Impact:** Low. The shapes are schema-exact. But an unrecorded difference, such as an extra non-JSON line from `agent start`, would only show up in INB-007.
- **Smallest fix:**
  1. State in the task's final summary (DoD #2) that these five answers are schema-built and unverified.
  2. Add an acceptance criterion or note to INB-007 to record them, including the error answer for a blocked startup (see F1), and swap them into the fixture.

### INB003-R1-F3: Minor. `ensureWorkspace` trusts a bare stored workspace id

- **Where:** `src/herdr/adapter.ts:148-152`.
- **Scenario:** The stored inbox workspace id is, say, `w7`. Later (after a Herdr restart or renumbering) that id belongs to one of the owner's own workspaces.
- **Expected:** Spec §10.2 says the inbox uses its own workspace and never borrows a project workspace. §10.3 says never trust a reused numerical id alone.
- **Actual:** Any workspace answering `workspace get w7` is reused, and launch tabs open in the owner's workspace.
- **Impact:** Launch tabs land in the wrong workspace. No context goes to the wrong session: the alias and bridge checks still guard that. It is unproven whether 0.9.5 reuses ids.
- **Smallest fix:** Compare the returned label with the configured inbox label as negative evidence. On a mismatch, return `{ mismatch: true }` (or treat it as gone) and let the caller decide. Do not reuse silently. Test it.

### INB003-R1-N1: Note. `agent_prompt_stalled` cannot occur

Herdr's help says it is returned only under `--wait`, and `prompt()` never sends `--wait`. Keeping it in the set is harmless. A one-line comment would stop a reader thinking `--wait` is in use.

### INB003-R1-N2: Note. `agent()` folds `agent_name_not_found` into null

- **Where:** `src/herdr/adapter.ts:194`.
- Herdr's message for this code is "named agent … no longer owns the target terminal", which means the occupant changed. That is different from "never existed".
- Spec §13 says fail only when closure is established. INB-006 should not read a null as "closed". Consider exposing the code.

### INB003-R1-N3: Note. Other selection variables are not scrubbed

- **Where:** `src/herdr/adapter.ts:102`.
- The binary also reads `HERDR_SESSION`, `HERDR_CLIENT_SOCKET_PATH` and `HERDR_ACTIVE_PANE_ID` / `HERDR_ACTIVE_WORKSPACE_ID`. None is set in a pane today.
- Dropping them too would make the socket the only server selector, whatever context the caller runs in (for example a plugin).

### INB003-R1-N4: Note. A trailing line after the JSON downgrades success to unknown

`parseEnvelope` reads only the last line of each stream. If Herdr ever prints an announcement after the JSON, a successful create becomes `unknown`. That is conservative and correct for safety, but worth knowing when INB-007 records the real output.
