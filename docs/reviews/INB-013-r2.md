**Page turn.**
- `update()` is a compare-and-set that retries on a miss, per index.d.ts `UpdateFunction`.
- It reads the latest stored page, so presses that arrive before a redraw add up.
- A handler from an older draw clamps with that draw's page count. The render clamps again, so nothing out of range is ever drawn. A stale handler after switching items costs at most one press doing nothing. Negligible.

**Scroll semantics** (index.d.ts, `scroll` and `UiScrollArgs`).

- The page-header Box sits at the same row on every page, because nothing above it depends on the page. The scroll is right whether it resolves against the tree before or after the redraw.

## Findings

### F1 — Minor — a bridge block during the focus phase is still labelled "Focus failed"

- **Where:** mod/hooks/text.ts:368, `if (a.phase === "focus")`.
- **Scenario:**
  1. The focus fails. The attempt is blocked with phase `focus`, which is correct so far.
  2. The person goes to that tab themselves and runs `/clear`, which starts a new session id.
  3. The bridge's SessionStart calls `bind()` (src/bridge/hooks.ts:90). A blocked attempt is still bindable.
  4. `bind()` sets blocked `RECEIPT_INVALID`, "Startup check failed: session id does not match the attempt.". It clears `receipt_candidate_json` (src/core/attempts.ts:484–490). The phase stays `focus`.
- The same can happen in the sub-second gap between the worker's settle check and its focus.
- **Expected:** the generic "Blocked: RECEIPT_INVALID", or a startup-mismatch label.
- **Actual:**
  - The pane shows "Focus failed: … Retry only focuses it again; nothing is resent. Startup check failed: …".
  - A retry would not just focus: there is no receipt any more, and the alias now reports a different session, so the attempt blocks again in verification.
- **Impact:** it needs the person to act after a focus failure, so it is rare. When it happens, the person is told the wrong cause and the wrong effect of Retry.
- **Smallest fix:** require the receipt too: `a.phase === "focus" && a.evidence.receipt_candidate`, optionally with `code === "AGENT_UNAVAILABLE"`. Add one unit case: phase focus, RECEIPT_INVALID, no receipt.
