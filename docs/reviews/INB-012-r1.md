## Findings

**R1-MIN-1 (Minor): emoji are under-counted, so row tails get cut.** `mod/hooks/text.ts:376-386`
- Scenario: a producer titles an item "✅ Build done 🚀", a common style for build notices.
- Expected: `width` matches what the terminal draws.
- Actual: `width("✅")`, `width("🚀")`, `width("⚠️")` and `width("🛠")` each return 1; they draw 2 cells. `rowLine(..., 40)` reports 40 cells and draws 42. `wrap="truncate-end"` then cuts the right end, which holds age and status, the most useful part of the row.
- Impact: status or age is lost on emoji titles. No wrap, no corruption.
- Smallest fix:
  - Add ranges 0x2600-0x27BF (the East Asian Width W subset, or simply 0x2614-0x2B55 W points), 0x1F000-0x1FAFF as one block, and 0x1F680-0x1F6FF.
  - Treat a character followed by U+FE0F as 2 cells.
  - Add an emoji case to `mod-text.test.ts`.

**R1-MIN-2 (Minor): rows from the old view stay on screen under the new view's tab.** `mod/hooks/register.tsx:184-188`
- Scenario: press `h` (History).
  - Until the next answer lands, the pane shows the Active rows under a highlighted History tab. `rowStatus` already applies History rules to them, so status shows blank.
  - If that call fails (e.g. STORE_BUSY), the Active rows stay indefinitely, under the error line.
- Expected: rows always belong to the view and filters drawn.
- Actual: `LIST` keeps `prev.rows` on error and is never cleared on a view or filter change.
- Impact: briefly, or until recovery, misleading. It does not trigger actions (none exist yet in INB-012), but INB-014 will act on the selected row.
- Smallest fix: store the asked argv (or view and filters) in `LIST`. Render rows only when it matches the current view and filters; otherwise show "Loading…" or the error alone.

**R1-MIN-3 (Minor): decisions.md states an unverified install fact.** `docs/decisions.md:203-205`
- The bullet says an installed folder-marketplace plugin is "read in place, so the same path holds after install".
- Claude Code's plugin docs describe copying installed plugins into a plugin cache, where `../` paths outside the plugin root stop resolving. This machine's one installed plugin lives under `plugins/cache`. Nothing in the repo shows a directory-marketplace install being checked.
- Impact: if the claim is wrong, `$.plugin.root/../src/cli/main.ts` breaks after INB-020 installs the mod, and `/inbox` shows MOD_CLI_FAILED in both profiles.
- Smallest fix: mark the bullet "to verify in INB-020" and list it in preflight §7. Alternatively, plan a fallback now: a configured CLI path in the inbox config, or an env var.

**R1-MIN-4 (Minor): an unexpected answer shape leaves the pane stuck and the error unseen.** `mod/hooks/register.tsx:190-191, 214-216`
- If `ok: true` arrives with `data.items` missing, or `$.ui.panes()`/`$.state` rejects, `fetchList` throws.
  - On the tick path that is an unhandled rejection (`void …then(…)`).
  - In `command.run` the hook throws, and the pane stays on "Loading…" with nothing shown.
- Expected: failures are loud in the pane (lens 6).
- Smallest fix: wrap the `fetchList` body in try/catch, writing `{ code: 'MOD_CLI_FAILED', message }` into `LIST.error`, and add `.catch` on the tick.

**R1-MIN-5 (Minor): the stale-answer drop is untested.** `mod/hooks/register.tsx:184`
- Deleting the argv comparison would still pass all 6 engine tests. "views and filters" presses only after each call completes.
- Smallest fix: one engine test with a slow CLI. Press `h` mid-call, then assert the Active answer never reaches `LIST` and the next call is `--view history`.

**R1-MIN-6 (Minor, unverified live): selection and keyboard focus look the same.** `mod/hooks/register.tsx:275-276`
- ButtonProps says a `plain` Button is inverted under focus. The selected row is also drawn `inverse`.
- While tabbing through rows (keyboard-only, spec §12.1), the focused row and the selected row cannot be told apart. On the selected row itself, both inversions apply.
- Smallest fix: mark selection with a leading glyph (e.g. `›` in place of the spacer) or `color`, not `inverse`. Check it live.

**R1-NOTE-1:** Filter values cycle only through profiles and producers already seen in returned rows. A producer whose items sit only in an unvisited view, beyond the 200-row page, or outside the current kind filter cannot be chosen yet. Acceptable for INB-012. Consider seeding from `status` or `profiles.json` later.

**R1-NOTE-2:** Snoozed rows never show `snoozed_until`, though `toRow` carries it. Not required by §12.1. A cheap win: show it in the status slot in the Snoozed view.

**R1-NOTE-3:** `inertDeep` writes `out[inert(k)]` onto a plain object. A `"__proto__"` key from JSON would set that object's prototype instead of a key. List answers have no producer-keyed maps. Worth using `Object.create(null)` or `Object.defineProperty` before INB-013 renders producer metadata or references.
