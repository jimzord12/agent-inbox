## Lenses

1. **Product fit and wiring.** Reconcile runs from the real CLI before every attempt-reading command (`main.ts:292-299`). The detached worker and `retry` reach the same `Worker` walk. Availability is reached only through `focus`. Spec §7's "the next explicit open/retry or UI startup reconciles" holds for the CLI. The mod will inherit it by calling the same commands.
2. **Correctness and edge cases.** Adapter calls are async (`Bun.spawn`), so the lease renew timer runs during long `agent start` waits. Lease times use the injected clock and step deadlines use `Date.now()`; the two never mix in one comparison. Overlapping reconcilers share the owner name `reconcile`, so the second claim succeeds over the first. Fencing then makes the first one's writes throw, and those throws are swallowed: harmless, as accepted in INB-009 r1 N2. Retry `resume` clears `last_rejection_json`, which disables reconcile's rejection-time guard after a retry (N3).
3. **Data integrity (lead).**
   - **False delivery.** Delivery happens in exactly two places: the worker's `focusAndCommit` and reconcile's commit shortcut. Both go through `commitDelivery`. That one transaction re-checks the fencing generation, revocation, `in_progress` status, binding, accepted prompt, receipt candidate, the item's current revision and that the item is not archived (`attempts.ts:424-460`). Reconcile commits only when focus is `confirmed`, which the worker writes only after the settled-state check (`reconcile.ts:54`, `worker.ts:473, 513`). The test at `worker.test.ts:941` kills that shortcut for a `started` or `uncertain` focus.
   - **Repeated prompt.** A second dispatch needs `prompt_state = rejected`, which only a definitive Herdr refusal sets, and only while the prompt is still `started` (`attempts.ts:371-375, 380-389`). `beginOp` refuses any recorded op (`attempts.ts:340-356`). A plain worker that meets a recorded op ends uncertain (`faults.test.ts:143`). Every probe ended with one prompt and one start.
   - **Expired leases.** PA shows the realistic stale-worker case. The prompt is typed after reconcile took over. The bridge still accepts on the uncertain attempt, the old worker's next write is fenced, and `crashed()` returns quietly. Retry then delivers without resending.
   - **Busy or full store.** Busy writes leave no partial state (IMMEDIATE transactions). The worker's reaction is safe in every PB case, but one error path is mislabelled (F1). A full store still lets reads and reconcile run (PF).
   - **Herdr restart.** The fake covers a new occupant, a missing alias and a counter reset (PE: blocks, never focuses). None of them is taken for the old session.
4. **Contracts and privacy.** No CLI JSON shape changed in a way that breaks the M1/M2 contracts. `get` gained `attempts` (INB-011). `STORE_ERROR {reason:"full"}` keeps the envelope. Privacy: none found.
5. **Tests and evidence.**
   - **Crash fidelity.** The crash spy wraps every worker-side `Attempts` write. After the trip point, every write throws, including the worker's own cleanup and `release`. The store therefore holds exactly what a killed process leaves, and the lease lapses on the fake clock. The bridge methods stay live, which is correct: the bridge is another process.
   - **Discrimination.** Each boundary case asserts the reconciled status, so a reconcile that commits on receipt alone fails the "after the receipt" case. Reconcile is asserted to make zero Herdr calls. Tab, start and prompt counts are asserted.
   - **Mutations.** Earlier rounds ran 17 deletion probes (INB-010) and 7 (INB-011). The survivors are redundant pairs (INB-010 N1). This milestone adds no unpinned guard beyond what those rounds found.
   - **Gaps.** No test covers a store error inside the Herdr try blocks (F1). No test covers the worker-side outcome of a busy UserPromptSubmit (N2). Mocks are used only at Herdr and the clock.
6. **Failure handling (lead).**
   - **Reconcile never breaks a read.** Each attempt sits in its own `try`, and the replay has an inner `try`. The first STORE_BUSY ends the pass, so a read waits at most one busy timeout. Any other error is swallowed (`worker.test.ts:974, 1004`). A full store does not break it (PF). Only `at.unfinished()` sits outside the loop's `try`. In WAL mode it does not meet a busy store, and the read itself would meet the same error anyway (N6).
   - **Failures are loud and recoverable.** Every unclear Herdr outcome ends `uncertain` with a message, and retry observes rather than repeats. Two paths are recoverable but less clear than they could be:
     - A busy store inside a Herdr step is reported as a Herdr outcome (F1).
     - A receipt saved aside is not picked up by a live worker until some CLI read runs (F2).
7. **Simplicity and ownership.** Reconcile is one small module that never calls Herdr. Core stays the only DB writer: the worker and reconcile go through `Attempts`. The bridge removes only its own sidecar file. No unasked scope.
8. **Repository and docs.**
   - Tasks: INB-009, INB-010 and INB-011 are Done, each with passed final rounds stored and dispositions in their notes. INB-023 is In Progress.
   - Carried items landed. INB-010 F1's test is at `faults.test.ts:143`. F2's decision is in `docs/decisions.md` ("A busy store at SessionStart is tried once more"). INB-009 r1 N4 and INB-011 r2 F1 are in INB-013's notes.
   - Commit subjects follow the convention. The INB-023 status change rode along in an INB-022 commit, which is cosmetic.

## Findings

### M2-R1-F1 - Minor - A store error inside a Herdr step is recorded as a Herdr outcome

- **Where:** `src/worker/worker.ts:261-278` (`createLayout`: `recordLayout` and `finishOp` inside the `createTab` try), `:319-338` (`startAgent`: `finishOp(start_agent, confirmed)` inside the try), `:426-439` (`submit`: `finishOp(dispatch_prompt, confirmed)` inside the try).
- **Scenario (probe PB2):** Herdr accepts the opening prompt. The following `finishOp(dispatch_prompt, confirmed)` meets STORE_BUSY. The Herdr `catch` takes it: `isRejected` is false, so the op is recorded `uncertain` with code `error`, and the log says "opening prompt outcome unknown (error)". In `startAgent` the same thing turns a confirmed start into `uncertain AGENT_UNAVAILABLE` "Claude may have started; its readiness is unknown: The inbox store is busy" (read from the code, same path).
- **Expected vs actual:** Expected: a store failure goes to `crashed()` as a store failure, and Herdr's answer, which was success, is not reinterpreted. Actual: it is recorded and shown as an unclear Herdr outcome.
- **Impact:** Low. No false delivery and no replay: PB2 still delivered with one prompt, and the start case is recovered by retry's `observeStart`. The diagnostics and the needless `uncertain` mislead the owner, and a mod that shows the error will say Herdr is at fault.
- **Smallest fix:** In those three `catch` blocks, put `if (!(err instanceof HerdrError)) throw err;` first, or move the store writes out of the `try`. `crashed()` already turns an unexpected error after an external step into `uncertain`. Add one fault test: busy at `finishOp(start_agent, confirmed)`, then expect the message to name the store and retry to deliver with one start.

### M2-R1-F2 - Minor - A receipt saved aside reaches a live worker only through some CLI read

- **Where:** `src/worker/worker.ts:445-484` (`awaitReceipt` never replays `receipt-pending.json`); `src/worker/reconcile.ts:36-43` (the only replayer).
- **Scenario (probe PD):** The Stop hook meets a busy store twice and saves the valid receipt aside. The worker keeps polling the store. No `agent-inbox` read happens in the next `receiptTimeoutMs` (10 min by default). The worker blocks with `RECEIPT_INVALID` "No valid acknowledgment yet". The next read replays the receipt, and retry delivers with one prompt.
- **Expected vs actual:** Expected: the worker that owns the attempt uses bridge evidence already on disk. Actual: it depends on an unrelated reader.
- **Impact:** Low. The attempt is recoverable and nothing is resent. The owner sees a needless block, and has to retry, after a short busy spell that the save-aside path was built to absorb. Once the mod polls `list`, the window mostly closes.
- **Smallest fix:** Export the pending-file replay and call it from the `awaitReceipt` loop before it reads the row, at most once per poll while the file exists. Or record in `decisions.md` that the mod's polling is the replay trigger.

## Notes

- **N1 (PE).** After a Herdr restart that resets `state_change_seq` below the dispatch baseline, retry blocks with "Claude has not settled after acknowledging" until the counter passes the old value. This is safe (never focuses), but the message misleads. Herdr's restart behaviour is unverified live, so look at it during the M6 runs.
- **N2.** A busy store at UserPromptSubmit makes the hook refuse the opening prompt (fail closed), but the refusal cannot be recorded. The worker then ends `uncertain` ("has not accepted the opening prompt; nothing was resent"), and only abandon plus a fresh open recovers. This is spec-conformant: an unrecorded refusal is not a definitive rejection. It costs a new session, and the worker side of it has no test.
- **N3.** `resume` clears `last_rejection_json` (`attempts.ts:418`), so after a retry the reconcile rejection-time guard (`reconcile.ts:96-99`) no longer protects against a late busy-Stop file from a session that `/clear` replaced. This is the same exposure as INB-009-R3-F1. There is no false delivery, because the worker checks Herdr's session id (`worker.ts:398, 468`).
- **N4.** The adapter classes every runner exception as `rejected` (`adapter.ts:149-151`), including one thrown after the child ran, for example while reading its output. For `agent prompt` that would allow a second dispatch on retry. It is very unlikely with `Bun.spawn`. It belongs to M2's adapter and is named here only for lens 3.
- **N5.** "TUI exit" is met for the CLI: the detached worker plus reconcile on read. The mod (M4) should call only these commands and add nothing that assumes old identity. Re-check under INB-012 to INB-014.
- **N6.** `receipt-pending.json` files of abandoned or closed attempts are never removed, because reconcile visits only unfinished attempts. This is harmless. `at.unfinished()` sits outside reconcile's per-attempt `try`, so its error surfaces as the read's own error, which is acceptable.
